# Proposed data and evidence contracts

**Specification only.** These fields describe future interfaces; they are not an implemented schema validator.

Every artifact has a stable ID, schema version, creation time, producing tool/version, input artifact IDs, configuration hash and content checksum. Unknown values are explicit nulls with a reason; they are never fabricated.

| Record | Required content |
| --- | --- |
| Study manifest | Study ID, sample IDs, sample roles, batch and injection order, experimental groups where applicable, control availability, acquisition protocol |
| Spectrum | Source file hash, native scan ID, MS level, precursor m/z and units, charge, polarity, collision energy and units, instrument, retention time and units, peak arrays, acquisition mode |
| Feature | Feature ID, sample ID, m/z, retention time, abundance and units, integration method/version, QC flags, linked spectrum IDs and linkage confidence |
| Embedding | Spectrum ID, checkpoint identifier/hash, upstream code revision, preprocessing configuration, vector dimensions, vector artifact hash and domain flags |
| Candidate annotation | Spectrum/feature IDs, candidate structure identifier, library accession/version, rank, raw score and score type, search settings, alternative candidates, confidence category and supporting evidence |
| Evidence claim | Claim ID, exact statement, evidence class, source/artifact ID, paper section or figure where relevant, limitations and review status |
| Review decision | Reviewer, timestamp, decision, rationale, evidence examined and any requested follow-up |
| Run manifest | Workflow version, dependency/container versions, input/output hashes, seeds where relevant, task states, exclusions, errors and resource usage |

## Evidence classes

- `paper_reported`: attributed to a published source, with a locator.
- `tool_computed`: generated by a recorded run; requires an actual artifact.
- `commentary`: interpretation that does not masquerade as a measurement.
- `proposed`: a future method or experiment.
- `hypothetical`: an illustrative scenario, excluded from performance claims.

No `tool_computed` records exist in this repository.

## Annotation states

Use descriptive internal states: `unannotated`, `candidate`, `putative`, `confirmed_with_reference_evidence`. They are not claimed to implement an external identification standard. A confirmed state requires reviewer-recorded experimental evidence and criteria, not a score threshold alone. Unresolved isomers must remain explicit.

A nullable calibrated probability must identify its calibration model and validation population. Without those, store only the original score and score type. Keep “not measured,” “failed QC” and “not detected” distinct.

## Validation requirements for implementation

Reject negative intensities, non-finite numbers, non-positive m/z values, unequal peak-array lengths, missing units and duplicate spectrum IDs within a run. Validate charge/polarity consistency. Check references between artifacts and hashes before using cached results. A valid file format alone does not establish analytical suitability.

Raw participant or proprietary data do not belong in the public repository. Example fixtures, if added later, should be synthetic or explicitly licensed for redistribution.
